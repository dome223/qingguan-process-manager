# 轻管：Windows 后台程序管理器

启动 `启动桌面版.bat`。需要 Windows、Python 3 和 Pillow（用于读取程序图标；可用 `py -m pip install Pillow` 安装）。帧时间采集器 PresentMon 2.6.0 已放在 `tools` 目录，许可证也随文件提供。

## 页面与进程管理

- 主窗口分为“进程管理”“实时监测”和“开机启动”三个页面，不另开管理窗口。
- 进程管理显示图标、名称、路径、签名发布者、PID、父进程、启动时间和工作集内存；支持搜索、内存排序、可见窗口/访问受限筛选和柔和的同路径颜色标识。重复分析只有一个入口，颜色及低频权限操作收在“更多操作”。
- 进程名称来自 Windows 进程快照；即使普通权限读不到路径或内存，条目仍会显示并标为受限。遇到 Windows 暂时无法生成快照时会有限重试；失败会保留上次列表，而不会悄悄显示成空列表。
- 磁盘筛选列出 Windows 当前分配盘符的所有挂载卷（包括映射盘），不再只从当前进程路径推断盘符。
- “重复分析”按完整程序路径分组，显示同路径进程树、PID、父 PID、启动时间和工作集；关系为快照启发式，不等于多余或可关闭。
- 顶部操作收在较紧凑的工具栏；“清单操作”菜单中选择导出分析清单或导入关闭清单。
- 左上角使用轻管自己的简洁图标。

## 开机启动管理

- “开机启动”页扫描当前用户/所有用户的注册表 Run/RunOnce 项、启动文件夹常见快捷方式/脚本、包含登录/开机触发器的计划任务，以及自动/延迟自动启动服务。32 位和 64 位注册表视图分别显示；读取失败会显示在“扫描问题”。
- 启动项按解析出的目标路径分组，展开后可看到各个独立入口、原始命令和可读取到的签名发布者；右键进程时按完整路径查找直接匹配项。命令包装器和应用内部启动器可能使目标无法精确对应，无法识别时会标出来。
- 选择具体入口后可停用或恢复。注册表项保留原值，快捷方式/脚本先备份并校验；计划任务、服务的原设置也会保存。旧版存放在用户 AppData 的停用记录会继续读取；新备份保存在程序目录 `startup_manager_data`。
- 停用只影响后续登录/开机，不会结束已经运行的程序。所有用户注册表、公共启动文件夹、计划任务和服务通常需要管理员权限；开机启动页提供“管理员模式”入口。
- 计划任务是整项启用/停用。若任务还含其他触发器（例如定时触发），仍会显示但不提供停用，以免连带影响其他计划任务功能。服务只调整启动类型，不停止正在运行的服务；停用时改为“手动”，应用或依赖项仍可能按需启动它，恢复时还原自动/延迟自动状态。系统目录中的服务、Microsoft Windows 计划任务会受保护，其他指向 Windows 目录的入口会提示风险。
- 这仍不是对所有 Windows 自启动机制的穷尽扫描：商店应用的专用 StartupTask、程序内部自启、驱动加载与厂商自定义机制可能不在列表里。注册表/启动文件夹项还可能被 Windows 的 StartupApproved 状态另行禁用，因此页面用“入口存在·状态待核”表示无法确认其最终启用状态。
- 判断建议：同目标分组只是多个入口指向同一目标，不表示重复进程或多余；“入口存在·状态待核”不能当作确认正在自启；签名未知也不能单独作为停用依据。目标无法识别时先核对原始启动命令；不能确认用途就先保留。计划任务含其他触发器时，到任务计划程序核对其余触发器，不在本工具里整项停用。

## 自动卡顿与内存监测

- 管理器启动后自动采样，无需你在游戏时点开始、停止或标记卡顿。
- “当前活动窗口”显示 Windows 当前前台进程，也是帧时间观察对象；管理器自己在前台时会显示“轻管（当前正在查看监测页）”，切回游戏后会自动显示游戏进程。它不是固定选择的监测目标。
- 每秒采集系统可用内存和进程工作集，内存环形历史最多保留约 30 分钟；界面曲线显示这段时间内的系统已用内存。
- PresentMon 通过 Windows 图形事件采集帧时间。对当前前台图形程序建立近期帧间隔中位数；当单帧间隔达到 `近期中位数 × 2.2` 与 `近期中位数 + 12 ms` 两者中较高者时，自动生成卡顿候选标记。三秒内同一程序的尖峰合并统计。
- 每个标记会等待并比较标记前后约 10 秒的进程工作集，列出增长较多的进程；双击事件可查看 PID、帧间隔、基线和路径。
- 帧时间异常是自动检测到的性能线索，不一定等于用户可感知卡顿；内存同时增长也不能单独证明它造成卡顿。帧时间分析受游戏 API、前台窗口状态、PresentMon 权限和驱动影响。OpenGL/Vulkan 等场景的部分帧指标精度可能较低。
- 当前账号若没有 ETW 采集权限，轻管先尝试以普通权限启动 PresentMon；若系统拒绝，本次轻管运行期间最多自动请求一次 UAC，仅提升 PresentMon 采集器，轻管本身保持普通权限。用户取消或启动失败后，内存监测继续，帧时间显示不可用；本次运行不重复弹窗。临时 CSV 放在用户本地 QingGuan 目录，退出时清理。PresentMon 的权限要求见 [官方说明](https://github.com/GameTechDev/PresentMon#user-access-denied)。
- 若 PresentMon 在启动后因非权限原因意外退出，管理器会自动重启采集器一次；权限错误不会自动反复重试或静默提权。重试仍失败时，内存采样继续，帧时间状态会显示不可用。
- 帧时间基线按 PID 和进程启动时间共同区分，避免 Windows 复用 PID 后沿用旧进程基线。新进程需等内存采样器识别到其启动时间后才纳入帧时间判断。
- 30 分钟明细保存在内存中，退出管理器后清空。自动标记和对应内存变化会纳入导出报告/分析清单。

## 报告和 AI 分析清单

- “导出报告”生成易读文本，包含当前进程、重复实例分析和已检测到的自动帧时间事件/内存变化。
- “清单操作 → 导出分析清单”生成 JSON。JSON 字段固定，包含重复组信息、每个实例的 PID/父 PID/启动时间/工作集/同路径关系，以及近期自动卡顿事件。
- 交给 AI 分析时，只让它修改 `instances[]` 每个具体实例内的 `action` 与 `reason`。可用 action：`review`、`keep`、`close`、`end_task`。禁止让 AI 在程序组上设置整组关闭动作；不确定当前是否在使用的实例应保持 `review`。
- “清单操作 → 导入关闭清单”只执行被明确标记的单个 PID 实例，不会连带关闭同程序组其余实例。程序检查电脑名、最新导出编号、程序文件标识、完整身份字段、PID 和高精度启动时间，并显示可滚动的逐 PID 确认清单；你确认后才执行。
- `close` 只向该 PID 的可见窗口发正常关闭请求；无可见窗口时不会强行结束。`end_task` 才会像任务管理器“结束任务”一样直接终止该 PID，可能丢失未保存内容。二者都不会删除文件或阻止以后启动；服务/主程序仍可能再次拉起它。
- schema 3 与之前的 schema 2 不兼容。程序更新后请重新导出清单，再交给 AI；不能导入旧的组级关闭清单。

## 重要限制

- 白名单/黑名单目前是本地标记，不会自动阻止启动或联网。
- 工作集数值可能包含共享页面；同组加总仅供比较，不是精确的独占物理内存。
- 签名发布者、安装路径、进程数量和父 PID 都不能单独证明程序安全、恶意或可关闭。Windows 核心进程、Windows 目录程序受保护；第三方驱动、安全软件、输入法和网络组件仍需人工确认。
- 结束任何进程前先保存文档。结束子进程可能让主程序重新创建它；这需要后续结合持续启动来源记录来确认。

## 第三方组件

帧时间采集使用 Intel/GameTechDev 的 [PresentMon 2.6.0](https://github.com/GameTechDev/PresentMon/releases/tag/v2.6.0)，依据其 MIT 许可证分发，许可证见 `tools/PresentMon-LICENSE.txt`。PresentMon 通过 ETW 收集帧呈现事件；详见 [PresentMon 项目说明](https://github.com/GameTechDev/PresentMon) 和 [Microsoft ETW 文档](https://learn.microsoft.com/en-us/windows/win32/etw/about-event-tracing)。
